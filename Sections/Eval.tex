\section{Evaluation}

\subsection{Experimental Setup}

We evaluate ADSD in the reproduced HSD workspace with:
\begin{itemize}
\item draft model: \texttt{Qwen2.5-0.5B-Instruct-GPTQ-Int8},
\item target model: \texttt{Qwen2.5-14B-Instruct-GPTQ-Int8},
\item verifier: token-wise speculative decoding,
\item hardware: RTX 4090 or A100 class GPUs for the 14B target,
\item benchmark: GSM8K prompting under the reproduced Qwen chat template.
\end{itemize}

The evaluation has two layers. First, we run the Palmetto soft-prefix search to
measure exact projected first-token collapse on the optimized boundary context.
Second, we inject either a matched boundary prefix or a calibration-batch
universal prefix into the same token-wise 263-sample GSM8K evaluation. All
end-to-end benchmark numbers in this section are therefore reported against the
same matched benign token-wise baseline.

\subsection{Metrics}

We report five metrics that capture both attack strength and user-visible
stealth:
\begin{itemize}
\item \textbf{First-token acceptance.}
$\alpha_1 = \min(1, p(y_1)/q(y_1))$ for the first drafted token after the
boundary prefix. This is the optimization target used to rank projected attack
candidates.
\item \textbf{Aggregate acceptance.}
The fraction of drafted tokens that are accepted by the verifier over a full
sample:
\[
\text{aggregate acceptance} =
\frac{\text{accepted drafted tokens}}{\text{drafted tokens}}.
\]
\item \textbf{Block efficiency.}
Accepted drafted tokens per verifier step:
\[
\text{block efficiency} =
\frac{\text{accepted drafted tokens}}{\text{target steps}}.
\]
\item \textbf{Mean sample time.}
Wall-clock generation time averaged over the 263 GSM8K prompts.
\item \textbf{Decoding speed.}
The HSD-style throughput statistic computed from the speculative counters in
the reproduced workspace. This complements wall-clock time with a counter-based
speed measure derived from accepted drafted tokens and elapsed decoding time.
\item \textbf{Accuracy.}
The standard GSM8K numeric-answer accuracy extracted from the evaluator output.
\end{itemize}

The key systems claim is not merely that $\alpha_1$ can be collapsed in
isolation, but that the resulting discrete attack degrades aggregate acceptance,
block efficiency, and runtime while leaving task accuracy essentially intact.

\subsection{Soft-Prefix Search Results}

The Palmetto search optimizes a five-token relaxed prefix and projects it to a
discrete boundary string. Across the sweep
$\lambda_{\rho}\in\{0.1, 0.25, 0.5, 1.0\}$, the optimizer consistently returns
the same projected attack and the same best exact first-token acceptance. The
manual comparison seed has exact $\alpha_1 = 0.1597$, while the optimized
projected prefix reaches $\alpha_1 = 0.0288$. Thus, after projection, the
search reduces verifier acceptance on the first drafted token by more than
$5\times$ relative to the hand-written seed.

This stability matters. It indicates that the attack is not an artifact of a
single penalty setting; the same discrete attack remains optimal across a
meaningful range of projection-distortion regularization strengths.

\subsection{Calibration-Batch Universal Prefix Search}

We next extend the attack from a single boundary context to a calibration-batch
universal prefix. For each calibration size $N \in \{1,2,4,8\}$, we optimize a
shared five-token prefix over $K=64$ target rollouts and then retain the best
projected prefix under the exact verifier-aligned ranking rule. The result is a
clear monotone pattern: every calibration size produces a stronger discrete
prefix than the manual seed, and every recovered universal prefix drives the
exact projected first-token acceptance to zero on its calibration batch.

that early verifier collapse is not restricted to a single hand-crafted

task behavior of the benign baseline almost exactly.

strongest universal-prefix attack ($N=2$), and the strongest
accuracy-preserving universal-prefix attack ($N=4$).

Table~\ref{tab:tokenwise-benchmark} captures the central empirical result of
the paper. The original boundary attack already increases runtime by about
$29\%$ while preserving task accuracy. The universal-prefix extension widens
the attack surface substantially. The $N=2$ universal prefix is the strongest
cost attack overall, pushing mean sample time to $51.60$s and cutting decoding
speed to $46.09$, but it also degrades GSM8K accuracy. The $N=4$ universal
prefix is the most important systems result: it raises mean sample time from
$23.10$s to $38.61$s ($+67.1\%$), lowers aggregate acceptance from $0.597$ to
$0.390$, lowers block efficiency from $5.832$ to $3.731$, and reduces decoding
speed from $79.55$ to $51.68$, while matching the benign GSM8K accuracy exactly
at $222/263$.

This is exactly the attack profile a systems paper should care about. If the
prefix merely caused nonsense outputs, the slowdown would be easy to dismiss as
degenerate prompting. Instead, the universal-prefix attack demonstrates that
speculative decoding can be driven into a materially less efficient regime
while preserving the user-visible task accuracy of the benign baseline.

\subsection{Interpretation}

Three conclusions follow.

First, first-token collapse is a useful attack primitive, not a misleading toy
metric. The soft search drives exact projected $\alpha_1$ from $0.1597$ down to
$0.0288$, and the calibration-batch universal search drives the projected
calibration $\alpha_1$ all the way to zero for every $N \in \{1,2,4,8\}$.
These projected prefixes then produce substantial end-to-end degradation on the
held-out token-wise evaluation.

Second, counter-based verifier metrics and wall-clock latency move in lockstep.
The attacks that lower aggregate acceptance and block efficiency also lower the
HSD-style decoding-speed statistic and raise real generation time. This
agreement makes the slowdown effect difficult to attribute to incidental
hardware noise alone.

Third, the attack is already practically meaningful at modest prompt budget.
The strongest accuracy-preserving result uses only a short five-token universal
prefix, yet it raises runtime by more than two thirds without requiring any
model parameter changes or API privileges beyond prompt control.

\subsection{Scope}

Our experiments focus on the token-wise verifier because it provides the
cleanest connection between the exact acceptance rule and the verifier-aligned
optimization objective. Within that setting, the empirical picture is already
clear: prompt-side optimization can translate isolated verifier collapse into a
large end-to-end slowdown, and calibration-batch universal prompting amplifies
that effect considerably.
