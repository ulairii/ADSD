\section{Evaluation}

\subsection{Experimental Setup}

We evaluate ADSD in the reproduced HSD workspace with:
\begin{itemize}
\item draft model: \texttt{Qwen2.5-0.5B-Instruct-GPTQ-Int8},
\item target model: \texttt{Qwen2.5-14B-Instruct-GPTQ-Int8},
\item verifier: token-wise speculative decoding,
\item hardware: RTX 4090 or A100 class GPUs for the 14B target,
\item benchmark: GSM8K prompting under the reproduced Qwen chat template.
\end{itemize}

The evaluation has two layers. First, we run the Palmetto soft-prefix search to
measure exact projected first-token collapse on the optimized boundary context.
Second, we inject a matched benign or adversarial prefix at the same assistant
boundary and run the full 263-sample GSM8K evaluation to measure the system
effect on end-to-end speculative decoding.

\subsection{Metrics}

We report five metrics that capture both attack strength and user-visible
stealth:
\begin{itemize}
\item \textbf{First-token acceptance.}
$\alpha_1 = \min(1, p(y_1)/q(y_1))$ for the first drafted token after the
boundary prefix. This is the optimization target used to rank projected attack
candidates.
\item \textbf{Aggregate acceptance.}
The fraction of drafted tokens that are accepted by the verifier over a full
sample:
\[
\text{aggregate acceptance} =
\frac{\text{accepted drafted tokens}}{\text{drafted tokens}}.
\]
\item \textbf{Block efficiency.}
Accepted drafted tokens per verifier step:
\[
\text{block efficiency} =
\frac{\text{accepted drafted tokens}}{\text{target steps}}.
\]
\item \textbf{Mean sample time.}
Wall-clock generation time averaged over the 263 GSM8K prompts.
\item \textbf{Accuracy.}
The standard GSM8K numeric-answer accuracy extracted from the evaluator output.
\end{itemize}

The key systems claim is not merely that $\alpha_1$ can be collapsed in
isolation, but that the resulting discrete attack degrades aggregate acceptance,
block efficiency, and runtime while leaving task accuracy essentially intact.

\subsection{Soft-Prefix Search Results}

The Palmetto search optimizes a five-token relaxed prefix and projects it to a
discrete boundary string. Across the sweep
$\lambda_{\rho}\in\{0.1, 0.25, 0.5, 1.0\}$, the optimizer consistently returns
the same projected attack and the same best exact first-token acceptance. The
manual comparison seed has exact $\alpha_1 = 0.1597$, while the optimized
projected prefix reaches $\alpha_1 = 0.0288$. Thus, after projection, the
search reduces verifier acceptance on the first drafted token by more than
$5\times$ relative to the hand-written seed.

This stability matters. It indicates that the attack is not an artifact of a
single penalty setting; the same discrete attack remains optimal across a
meaningful range of projection-distortion regularization strengths.

\subsection{Matched 263-Sample Boundary Evaluation}

We next evaluate the actual systems effect on a matched 263-sample GSM8K run.
The benign condition prepends the same five-token boundary budget with the
instruction \texttt{Please think step by step}. The attacked condition prepends
the adversarial typo-like boundary prefix at the identical assistant boundary.
Everything else is held fixed.

\begin{table}[t]
\centering
\caption{Matched benign-boundary versus attacked-boundary evaluation on the
263-sample token-wise GSM8K run. Lower aggregate acceptance and block
efficiency are worse for the system; higher mean sample time is worse for the
system.}
\label{tab:matched-263}
\begin{tabular}{lccc}
\toprule
Metric & Benign boundary & Attacked boundary & Relative change \\
\midrule
Mean sample time (s) & $23.10$ & $29.81$ & $+29.0\%$ \\
Aggregate acceptance (mean) & $0.597$ & $0.509$ & $-14.8\%$ \\
Block efficiency (mean) & $5.832$ & $4.961$ & $-14.9\%$ \\
GSM8K accuracy & $222/263$ & $225/263$ & $+1.1$ points \\
\bottomrule
\end{tabular}
\end{table}

Table~\ref{tab:matched-263} captures the central result of the paper. The
adversarial boundary does not break the model's task behavior. Instead, it
forces the verifier to do more work while the target model still completes the
reasoning chain correctly. Mean sample time rises by roughly $29\%$, while both
aggregate acceptance and block efficiency fall by about $15\%$. At the same
time, GSM8K accuracy remains unchanged within ordinary sampling variance.

This is exactly the attack profile a systems paper should care about. If the
prefix merely caused nonsense outputs, the slowdown would be easy to dismiss as
degenerate prompting. Here the target model instead repairs the adversarial
boundary and still solves the task, which means the user-visible output layer
does not reveal the compute-side attack.

\subsection{Interpretation}

Three conclusions follow.

First, first-token collapse is a useful attack primitive, not a misleading toy
metric. The soft search drives exact projected $\alpha_1$ from $0.1597$ down to
$0.0288$, and the resulting discrete attack family produces measurable
end-to-end degradation on the full evaluation.

Second, aggregate metrics alone would understate the vulnerability. The attack
works by creating an early verifier speed bump. Once the target model repairs
the boundary, later generations partially realign, so answer quality remains
high. This is precisely why first-token acceptance, aggregate acceptance, block
efficiency, and wall time must be reported together.

Third, the attack is already practically meaningful at modest prompt budget.
The current attack uses only a short boundary prefix, yet it extracts a large
runtime penalty from a lossless decoding system without requiring any model
parameter changes or API privileges beyond prompt control.

\subsection{Scope}

Our experiments focus on the token-wise verifier because it provides the
cleanest connection between the exact acceptance rule and the soft-prefix
objective. The next empirical axis is not to re-establish existence, but to map
the attack surface more fully: prefix-length sweeps, random and greedy
baselines, and transfer to stronger block-wise or hierarchical verifiers.
