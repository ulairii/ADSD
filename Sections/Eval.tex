\section{Evaluation}
\label{sec:eval}

\subsection{Experimental Setup}

We evaluate ADSD in the reproduced HSD workspace of
\citet{zhou2026hsd} using \texttt{Qwen2.5-0.5B-Instruct-GPTQ-Int8} as the
draft model and \texttt{Qwen2.5-14B-Instruct-GPTQ-Int8} as the target model
under token-wise speculative verification. The benchmark is GSM8K with the
reproduced Qwen chat template, and the reported end-to-end runs use RTX 4090
or A100-class GPUs for the 14B target. The evaluation has two layers. First,
we run the Palmetto soft-prefix search to measure exact projected first-token
collapse on an optimized single-prompt context. Second, we inject either a matched
single-prompt prefix or a calibration-batch universal prefix into the same
263-sample token-wise GSM8K evaluation. All end-to-end numbers in this section
are therefore reported against the same matched benign token-wise baseline.

Each benchmarked GSM8K run uses the same evaluator configuration: batch size
one, stochastic decoding (\texttt{do\_sample=True}), a per-sample cap of
\texttt{max\_new\_tokens=512}, and the same speculative verifier settings
across all compared conditions. Per-sample wall-clock latency is recorded as
the elapsed time around the actual speculative \texttt{generate(...)} call in
the reproduced evaluator. Aggregate acceptance, block efficiency, and
decoding-speed summaries follow the same counter-based bookkeeping exposed by
the HSD evaluator and are computed from the saved speculative traces
\texttt{draft\_eval}, \texttt{sample\_length}, and \texttt{total\_step}
\citep{zhou2026hsd}. This distinction matters: runtime is a real systems
measurement, while the counter-based metrics provide hardware-agnostic views of
the underlying verifier behavior. Evaluating at batch size one is deliberate
and follows standard speculative-decoding practice
\citep{leviathan2023speculative,zhou2026hsd}: the object of study here is the
per-sequence verifier mechanism itself, not downstream batching or router
scheduling.

\subsection{Metrics}

We report six metrics that capture both systems degradation and user-visible
stealth. First-token acceptance measures the collapse of the earliest verifier
event and is the exact projected quantity used to rank retained attack
candidates during search. Aggregate acceptance reports how much drafted work
survives verification over a full sample. Block efficiency measures how many
accepted drafted tokens are recovered per verifier step. Mean sample time is
the wall-clock generation time averaged over the 263 GSM8K prompts. Decoding
speed is the HSD-style throughput statistic computed from the speculative
counters in the reproduced workspace \citep{zhou2026hsd}. Finally, accuracy is
the standard GSM8K numeric-answer accuracy extracted from the evaluator
output. The key systems claim is not merely that first-token acceptance can be
collapsed in isolation, but that the resulting discrete attack degrades
aggregate acceptance, block efficiency, decoding speed, and runtime while
leaving task accuracy essentially intact.

\subsection{Calibration-Batch Universal Prefix Search}

We next extend the attack from a single-prompt setting to a calibration-batch
universal prefix. For each calibration size $N \in \{1,2,4,8\}$, we optimize a
shared five-token prefix over $K=64$ target rollouts and then retain the best
projected prefix under the exact verifier-aligned ranking rule. The result is a
clear monotone pattern: every calibration size produces a stronger discrete
prefix than the manual seed, and every recovered universal prefix drives the
exact projected first-token acceptance to zero on its calibration batch.

The calibration-batch attack is important for two reasons. First, it confirms
that early verifier collapse is not restricted to a single hand-crafted

task behavior of the benign baseline almost exactly.

Table~\ref{tab:tokenwise-benchmark} captures the central empirical result of
the paper. The universal-prefix extension substantially widens the attack
surface beyond any single prompt instance. The $N=2$ universal prefix is the
strongest cost attack overall, pushing mean sample time to $51.60$s and
cutting decoding speed to $46.09$, but it also degrades GSM8K accuracy. The
$N=4$ universal prefix is the most important systems result: it raises mean
sample time from $23.10$s to $38.61$s ($+67.1\%$), lowers aggregate acceptance
from $0.597$ to $0.390$, lowers block efficiency from $5.832$ to $3.731$, and
reduces decoding speed from $79.55$ to $51.68$, while matching the benign
GSM8K accuracy exactly at $222/263$.

This is the attack profile that makes speculative inefficiency a real systems
problem rather than a prompt oddity. If the prefix merely caused obviously
degraded outputs, the slowdown could be dismissed as degenerate prompting. In
contrast, the universal-prefix attack drives the verifier into a materially
less efficient regime while preserving the user-visible task accuracy of the
benign baseline.

\subsection{Interpretation}

Three conclusions follow.

First, first-token collapse is a useful attack primitive, not a misleading toy
metric. The soft search drives exact projected $\alpha_1$ from $0.1597$ down to
$0.0288$, and the calibration-batch universal search drives the projected
calibration $\alpha_1$ all the way to zero for every $N \in \{1,2,4,8\}$.
These projected prefixes then produce substantial end-to-end degradation on the
held-out token-wise evaluation.

Second, counter-based verifier metrics and wall-clock latency move in lockstep.
The attacks that lower aggregate acceptance and block efficiency also lower the
HSD-style decoding-speed statistic and raise real generation time. This
agreement makes the slowdown effect difficult to attribute to incidental
hardware noise alone.

Third, the attack is already practically meaningful at modest prompt budget.
The strongest accuracy-preserving result uses only a short five-token universal
prefix, yet it raises runtime by more than two thirds without requiring any
model parameter changes or API privileges beyond prompt control.

\subsection{Adaptive Defenses}

One natural defense is to detect persistent acceptance collapse and halt
drafting adaptively, as in designs such as AdaEDL. Such a fallback is useful,
but it does not eliminate the vulnerability studied here. The attacker does
not need to force the system into a permanently degraded regime to succeed; it
is already sufficient to deny the request the intended speculative speedup.
Moreover, adaptive fallbacks require an observation window before the system
can decide that drafting is no longer beneficial. The attack therefore still
extracts a penalty during the detection phase, after which the request is
reduced to ordinary autoregressive decoding rather than accelerated
speculative decoding. From the adversary's perspective, that outcome remains a
successful worst-case degradation of the algorithmic mechanism.

\subsection{Scope}

Our experiments focus on the token-wise verifier because it provides the
cleanest connection between the exact acceptance rule and the verifier-aligned
optimization objective. Within that setting, the empirical picture is already
clear: prompt-side optimization can translate isolated verifier collapse into a
large end-to-end slowdown, and calibration-batch universal prompting amplifies
that effect considerably.
